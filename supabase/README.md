# 블로그 DB

연결된 Supabase 프로젝트 `mjauqslbtcjmlvlfxoga`의 기존 PostgreSQL에 블로그 전용 테이블을 추가합니다.
프로젝트나 물리 데이터베이스를 새로 만들지 않으며, 기존 테이블과 구분하도록 `public.blog_` 접두사를 사용합니다.

| 테이블 | 용도 | 공개 키 조회 |
| --- | --- | --- |
| `blog_posts` | 제목·저자·분류·작성일·공개 여부 | 공개 + 동기화 완료 + 삭제되지 않은 글 |
| `blog_post_contents` | 기존 NotionX 렌더러용 본문 JSON·검색 텍스트·읽기 시간 | 부모 글이 공개된 경우 |
| `blog_post_links` | 댓글 멘션 또는 수동으로 만든 책 연결 | 양쪽 글이 모두 공개된 경우 |
| `blog_sync_events` | 웹훅 이벤트 중복 방지·처리 상태·재시도 | 불가 |
| `blog_sync_state` | 원본 DB별 마지막 전체 동기화·성공·오류 시점 | 불가 |

## 적용

`migrations/`의 SQL을 파일 이름 순으로 Supabase SQL Editor 또는 관리자 연결로 한 번씩 실행합니다.
전체 적용은 하나의 트랜잭션입니다. 이미 같은 이름의 객체가 있으면 실패하며 기존 객체를 덮어쓰지 않습니다.
이 파일은 적용 이력을 보관하는 원본이며, 이후 변경은 새 마이그레이션 파일로 추가합니다.

적용 후 `tests/blog_access.sql`로 실제 `anon`, `authenticated`, `service_role` 권한을 검증할 수 있습니다.
임시 글·본문·연결·이벤트를 넣어 공개 범위, 공개 해제, 삭제 연쇄 처리, 웹훅 중복 방지를 확인한 뒤 전체 롤백합니다.
테스트는 기존 행을 수정하지 않습니다.

공개 키와 로그인 사용자에게는 읽기만 허용합니다. 글 작성·동기화·삭제는 서버의 `service_role` 권한이 필요합니다.
`SUPABASE_ACCESS_TOKEN`은 프로젝트 관리용 토큰입니다. 브라우저에 노출하거나 애플리케이션용 비밀 키 대신 사용하지 않습니다.

## 동기화 계약

- 글 ID는 Notion 페이지 UUID를 그대로 써서 기존 블로그 URL을 유지합니다.
- 새 글은 기본적으로 `is_published = false`, `sync_status = 'pending'`입니다. 메타데이터·본문·연결 저장을 마친 뒤 한 트랜잭션에서 `ready`로 공개합니다.
- 공개 해제·보관·삭제 시 기존 행의 `is_published = false`, `deleted_at`을 설정합니다. 본문을 물리 삭제하지 않으며, 다시 공개하면 같은 ID로 갱신하고 `deleted_at`을 비웁니다. 본문과 연결도 RLS로 함께 숨겨집니다.
- 본문은 목록 메타데이터와 분리해, 목록 조회에서 모든 본문을 전송하지 않습니다.
- 댓글은 연결된 책 ID만 저장합니다. 댓글 원문·작성자·통합 토큰은 저장하지 않습니다.
- 웹훅 `event_id`는 중복 저장되지 않습니다. 작업자는 이벤트 시각과 현재 Notion 수정 시각을 확인해 중복·순서 역전을 처리해야 합니다.
- 이미지 파일은 후속 동기화 구현에서 저장소로 복사해야 합니다. 만료되는 Notion 첨부 URL만 영구 본문에 저장하지 않습니다.

## 최초 수집·재동기화

```bash
# 서버 비밀 키 또는 service_role 키를 설정한 경우
npm run sync:notion

# 현재 관리용 클라우드 환경의 SUPABASE_ACCESS_TOKEN을 사용하는 일회성 실행
NODE_USE_ENV_PROXY=1 npm run sync:notion -- --management

# 특정 페이지의 공개 해제를 확인하고 소프트 삭제
NODE_USE_ENV_PROXY=1 npm run sync:notion -- --management --page PAGE_ID
```

CLI는 기존 환경변수와 `.env.local`을 읽고, Notion 요청을 약 2.5회/초로 제한합니다. 공개 필터를 적용한 전체 목록만 읽으며, 처음부터 비공개인 글은 DB에 새 행을 만들지 않습니다.
메타데이터·본문·검색 텍스트·읽기 시간·댓글 연결을 준비한 뒤 공개 목록과 수정 시각을 다시 확인하여 한 트랜잭션으로 저장합니다.
기존 DB 행 중 공개 목록에서 빠진 글은 소프트 삭제합니다. 조회 실패·불완전한 페이지 수집은 전체 교체를 실행하지 않습니다. 성공적으로 확인된 빈 공개 목록은 전체 공개 해제로 취급합니다.
중복 실행은 글 ID 기준으로 갱신하며, DB 시각을 사용해 나중에 끝난 오래된 스냅샷이 최신 변경이나 공개 해제를 되돌리지 못하게 합니다.
단일 페이지의 공개 해제는 해당 행만 소프트 삭제합니다. 그 글의 제목을 본문에 저장한 다른 글은 `pending`으로 숨기고 다음 전체 수집에서 비공개 멘션을 제거한 본문으로 복구합니다.
API 404는 권한 상실일 수도 있으므로 단독으로 공개 해제라고 판단하지 않습니다. 공개 페이지의 `--page` 실행은 현재 전체 공개 목록을 새로 수집합니다.
`tests/notion_sync.sql`은 실제 DB 역할에서 소프트 삭제·복구·오래된 작업 거절·전체 트랜잭션 원자성을 검사한 뒤 모두 롤백합니다.

웹훅 수신·서명 검증·개별 글 갱신·중복 방지·재시도 작업자를 구현했습니다. **운영 구독 연결은 [WEBHOOK.md](WEBHOOK.md)의 Notion 확인 및 Vercel 환경변수 설정이 필요합니다.**
첨부 파일의 영구 저장소 복사와 블로그의 DB 조회 전환은 아직 연결하지 않았습니다.
현재 본문 JSON과 커버에는 만료될 수 있는 원본 Notion 파일 URL이 있으므로, 이미지 저장소 연결 후에 블로그의 읽기 경로를 전환해야 합니다.
웹훅 설정 완료 전에는 CLI 재실행 시 변경이 반영됩니다. 설정 후에는 Notion 이벤트 수신으로 자동 갱신됩니다.
